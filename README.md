## 4. Олсон согог (lab05-defects.json)

Үндсэн collection ногоон (PASS) хэвээр байхын тулд согогийн тестүүдийг тусдаа collection-д хийсэн. Эдгээр нь зөв ёстой зан үйлийг хүлээдэг тул одоогийн server.js дээр унах нь хэвийн (results/newman-defects.txt: 13 assertion, 5 нь унасан).

| ID | Тест | Хүлээгдэж байсан | Бодит |
|---|---|---|---|
| D1 | Нэг оюутан нэг хичээлд 2 удаа бүртгүүлэх | 2-р бүртгэл 201 биш | 2-р бүртгэл ч 201 |
| D2 | Үүсгээгүй studentID = "constructor" | ERROR_NO_STUDENT | ERROR_INACTIVE_STUDENT |
| D3 | Үүсгээгүй studentID = "toString" | ERROR_NO_STUDENT | ERROR_INACTIVE_STUDENT |
| D4 | courseID = "toString" (идэвхтэй оюутан) | ERROR_NO_COURSE | сервер унаж, холболт тасарна (socket hang up) |

Шалтгаан: сервер оюутан, хичээлээ энгийн объектод хадгалдаг тул constructor, toString, __proto__ зэрэг нэр Object.prototype-оос олддог. Тэр үед оюутны status нь undefined тул ERROR_INACTIVE_STUDENT буцаана. Хичээлийн хувьд course.prerequisites нь undefined тул .filter дуудахад алдаа шидэж сервер унана. Давхар бүртгэлийн шалгалт серверт огт байхгүй.

## 5. Дүгнэлт

Би бие даан тестлэх функцээр POST /registrations-ийг сонгосон, учир нь энэ нь оюутан, хичээл, урьдач гэсэн хэд хэдэн оролттой бөгөөд олон төрлийн алдаа буцаадаг цорын ганц функц. Дөрвөн сонголт (studentID, courseID, prerequisites, хүсэлтийн формат) тус бүрийг эквивалент ангид хувааж, анги бүрээс төлөөлөх утга авч 14 тест гаргасан. Дизайны алхмуудаас хамгийн их бодол шаардсан нь давхар алдааны хослол байсан, учир нь нэг хүсэлтэд хэд хэдэн алдаа зэрэг байвал аль нь буцахыг заавар заагаагүй. T08–T10 тестээр сервер оюутны шалгалтыг (байхгүй, идэвхгүй) хичээл болон урьдачийн шалгалтаас өмнө хийдгийг тогтоосон. Боломжгүй хослол нь байхгүй оюутан дээр coursesTaken-ийг, байхгүй хичээл дээр prerequisites-ийг хослуулах явдал, учир нь ийм өгөгдөл огт оршдоггүй тул тэдгээрийг тестэд оруулаагүй. Тест бүр өөрийн PUT setup-тай тул шинэ асаасан сервер дээр бие даан ажиллах бөгөөд baseUrl нь collection variable тул collection дангаараа ажиллана. PASS ажиллуулалт 48 assertion, 0 унасан, exit code 0; FAIL хувилбарт нэг oracle-ийг зориуд буруу болгосон тул 1 assertion унаж exit code 1; DOWN дээр сервер унтарсан тул ECONNREFUSED гарсан бөгөөд энэ нь oracle-ийн биш холболтын алдаа. Тестүүд серверийн 4 согог олсон: нэг оюутныг нэг хичээлд давхар бүртгэхэд хоёулаа 201 буцаах, үүсгээгүй studentID нь constructor эсвэл toString үед ERROR_NO_STUDENT-ийн оронд ERROR_INACTIVE_STUDENT буцаах, courseID нь toString үед сервер унах. Шалтгаан нь сервер оюутан, хичээлээ энгийн объектод хадгалдаг тул constructor, toString зэрэг нэр Object.prototype-оос олддог явдал. Бүх happy path тест тэнцсэн ч эдгээр согог үлдсэн тул тестийн зорилго нь pass болгох биш, хязгаарын болон хачин оролтоор согог олох гэдгийг ойлгосон.
